# Writing docs

Rules for the docs. The rules in the root `AGENTS.md` apply too.

- **Each topic has one home.** Before you write, look for the doc that already covers the subject (`docs/README.md` lists them) and add to that. Don't start a new doc without asking.
- **Say it once.** If two docs explain the same thing, keep it in the more specific one and replace the other copy with a link.
- **Docs describe how things are now.** No history ("we used to"), no plans dressed up as facts. History goes in `CHANGELOG.md`, plans go in `TODO.md`.
- **Cite real paths.** Every path, command and symbol you mention must exist. Check before you write it.
- **Plain words, short sentences.** Write for a developer who is new to the project and in a hurry. Explain why, not only what.
- **Update `docs/README.md`** when you add, rename or remove a doc.

When code and docs disagree, find out which is right before changing either. If you can't tell, ask.
